# CodexSwitcher Mac 需求文档

## 1. 项目背景

重度使用 Codex/ChatGPT 编码能力的用户，常常同时持有 2~3 个账号。当前痛点主要集中在：

- 无法直观看到各账号额度状态与恢复时间
- 当主账号额度接近上限时，切换账号步骤多、打断工作流
- 切换后上下文容易断，任务接续成本高
- 用户不清楚应优先官方扩容还是切换备用账号

本项目定位为 `额度可视化 + 一键切换 + 会话接力 + 官方扩容优先` 的本地效率工具，不定位为绕过平台限制的自动化规避工具。

## 2. 产品目标

### 2.1 核心目标

- 让用户实时看到多个账号当前额度健康度
- 在额度不足时，帮助用户快速完成切换决策
- 在切换前后保留任务上下文，降低中断感
- 在高风险时优先提醒官方扩容路径

### 2.2 非目标

- 不承诺“完全无感永久自动切换”
- 不做共享账号分发平台
- 不做破解登录态或规避风控能力
- 不依赖不稳定的外部隐式接口作为唯一数据源

## 3. 目标用户

- 持有 2~3 个 Codex/ChatGPT 账号的重度开发者
- 高频使用 Codex CLI、ChatGPT、Agent 工作流的独立开发者
- 需要在多账号之间进行稳定接力的 AI 工具深度用户

## 4. 核心场景

### 4.1 额度查看

用户通过 Menubar 或主窗口查看：

- 当前活跃账号
- 各账号状态：健康 / 预警 / 耗尽 / 登录失效 / 异常
- 预计恢复时间
- 推荐下一账号

### 4.2 额度预警

当活跃账号达到阈值时：

- 展示风险提醒
- 优先展示官方扩容建议
- 同时给出推荐备用账号
- 支持稍后提醒

### 4.3 一键切换

用户选择备用账号后：

- 检测目标账号状态
- 可选生成接力卡片
- 执行切换
- 成功则刷新状态并写入日志
- 失败则提示原因并回滚

### 4.4 会话接力

切换前后生成结构化接力卡片，包含：

- 当前任务名称
- 当前目标
- 已完成项
- 未完成项
- 最近修改文件
- 最近命令
- 建议续接 Prompt

## 5. 核心功能需求

## 5.1 Menubar 常驻入口

- 展示当前活跃账号与健康状态
- 展示推荐动作
- 支持快速切换账号
- 展示最近一张接力卡片入口
- 支持打开主窗口和设置

## 5.2 账号中心

- 添加账号、删除账号、编辑账号昵称
- 设置默认账号
- 展示当前 Codex 官方登录态邮箱与官方账号 ID
- 当当前官方登录态尚未绑定时，必须提示用户点击“绑定当前已登录账号”加入账号列表
- 展示账号状态与最近检测时间
- 展示恢复时间、真实校验状态、可切换状态
- 支持重新登录/修复授权

## 5.3 额度检测与可视化

- 支持 5h / 7d 窗口概览
- 展示当前账号 `5h 已用`、`7d 已用`、`5h 预计恢复`、`7d 预计恢复` 与风险标签
- 展示最近 24h / 3d / 7d 用量历史图表
- 标记预警点、耗尽点、恢复点、切换事件
- 给出高峰时段摘要

## 5.4 一键切换

- 切换前校验目标账号可用性
- 支持切换前生成接力卡片
- 切换后验证健康状态
- 切换失败自动回滚
- 记录切换日志

## 5.5 账号时间轴视图

- 展示未来 3h / 6h / 12h 多账号可用性泳道
- 输出推荐切换时机
- 输出推荐切换路径摘要
- 标记数据可信度：真实 / 未知

## 5.6 官方扩容优先

- 达到阈值时优先展示官方扩容建议
- 支持用户关闭或调整优先级
- 切换账号作为备选动作而非唯一动作

## 5.7 通知中心

- 系统通知
- 预警通知
- 登录失效通知
- 切换成功/失败通知
- 恢复时间提醒

## 6. 信息架构

- Menubar 首页
- 主窗口仪表盘
- 账号中心
- 接力中心
- 通知中心
- 设置中心

## 7. Mac 平台特性要求

- 优先采用 Menubar 形态，支持仅菜单栏运行
- 敏感信息存储必须走 macOS Keychain
- 风格需贴近原生 macOS 效率工具
- 支持系统通知、开机启动、前后台检测策略
- 窗口尺寸和交互需兼顾小屏 MacBook

## 8. UI 风格与设计规范

### 8.1 设计定位

UI 需要走 `简洁大方、小清新、轻量 SaaS 工具感` 路线，不做赛博霓虹、重科技感或过度炫技界面。

视觉气质建议：

- 60% `Cal.com` 式 clean neutral 结构
- 25% `Notion` 式 warm soft surface
- 15% `Linear` 式 precise spacing

设计参考来源：

- `awesome-design-md`
- macOS 原生效率工具
- 浅色、克制、可扫描的数据仪表盘

### 8.2 视觉关键词

- 浅色
- 轻盈
- 有空气感
- 安静
- 克制
- 开发者工具感

### 8.3 明确禁止

- 不做深色主界面为默认形态
- 不做紫色偏置和高饱和霓虹渐变
- 不做过重玻璃拟态
- 不做夸张投影和复杂装饰图形

### 8.4 色彩规范

- 页面背景：`#F7FAF8`
- 主卡片背景：`#FFFFFF`
- 次级背景：`#F1F6F4`
- 主文字：`#1F2A24`
- 次文字：`#5F6B66`
- 描边：`#E3ECE8`
- 主色：`#58C2A8`
- 主色 Hover：`#46B196`
- 信息蓝：`#6FAFEF`
- 预警黄：`#F2C66D`
- 危险红：`#E97B73`

### 8.5 字体与层级

- macOS 优先使用 `SF Pro Display / SF Pro Text`
- 标题不使用衬线字体
- 信息层级要简洁，不堆大段说明

推荐字号：

- H1：28/34，600
- H2：22/28，600
- H3：18/24，600
- Body：14/22，400
- Meta：12/18，500
- Number Highlight：24/28，600

### 8.6 间距与圆角

- 采用 4pt 栅格
- 页面边距：24
- 模块间距：20
- 卡片内边距：20
- 表单项间距：12
- 大卡片圆角：20
- 普通卡片圆角：16
- 按钮和输入框圆角：12

### 8.7 阴影规范

- 只允许轻阴影：`0 8 24 rgba(30, 60, 50, 0.06)`
- 禁止多层重阴影

### 8.8 组件规范

按钮：

- 主按钮：主色实心
- 次按钮：白底 + 细描边
- 危险按钮：仅用于删除、清理等危险操作

状态标签：

- 健康：浅绿底深绿字
- 预警：浅黄底深黄字
- 不可用：浅红底深红字
- 未知：浅蓝底深蓝字

图表：

- 折线宽度 3px
- 面积填充透明度 10%~14%
- 预警点黄色
- 耗尽点红色
- 恢复点绿色
- 切换事件使用细竖线和小标签

### 8.9 首页结构要求

首页第一屏顺序固定为：

1. 当前活跃账号总览卡
2. 多账号状态概览卡
3. 用量历史图表
4. 账号时间轴视图
5. 推荐动作卡

### 8.10 Menubar 结构要求

Menubar 第一屏必须看到：

- 当前活跃账号
- 当前状态与百分比
- 推荐动作
- 最近接力卡片入口
- 打开主窗口/设置入口

### 8.11 首页文案要求

- 文案偏产品工具语气，不做营销口吻
- 预测类文案必须写为“预计”“建议”，无法基于真实数据判断时必须写“未知”
- 不允许写成绝对承诺式表述

## 10. MVP 范围

### P0

- Menubar 常驻
- 多账号管理
- 当前活跃账号展示
- 阈值提醒
- 一键切换
- 简版接力卡片
- 官方扩容优先提示
- 设置页基础项

### P1

- 用量历史图表
- 推荐最优账号
- 切换失败自动回滚
- 接力历史列表

### P2

- 账号时间轴视图
- 智能切换时机推荐
- 高峰时段识别
- 更细粒度通知策略

## 11. 验收标准

- 用户可管理 2~5 个账号
- Menubar 中可在 3 秒内发起并完成切换结果反馈
- 切换失败时保留当前活跃账号配置
- 接力卡片可查看、复制、编辑
- 历史图表可展示最近 7 天采样趋势
- 时间轴视图能输出未来可用性建议

## 12. 风险与注意事项

- 平台规则、额度口径、登录态可能变化
- 预测与推荐只能基于真实快照；缺少真实数据时必须显式展示未知
- 产品必须持续强调“官方扩容优先”
- 任何“完全自动切换”能力都要谨慎评估合规与稳定性
