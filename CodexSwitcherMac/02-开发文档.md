# CodexSwitcher Mac 开发文档

## 1. 当前工程状态

`CodexSwitcherMac` 已不是静态 prototype，而是一个可构建的真实工程，当前技术栈已经落地为：

- 桌面端：`Tauri 2 + React 19 + TypeScript`
- 本地服务与系统能力：`Rust`
- 数据存储：`SQLite / rusqlite`
- 凭证存储：`macOS Keychain`
- 前后端通信：Tauri `invoke(...)`

当前前端可以通过 `npm run build` 构建，Rust 侧已经承载真实账号、真实登录、真实采样、真实切换、通知、接力卡、启动健康检查与清理诊断等能力。

## 3. 当前前端结构

### 3.1 主入口职责

当前前端已经形成两层职责分工：

#### `src/App.tsx`

主要保留：

- 全局状态
- `useMemo` 派生状态
- `useEffect` 生命周期与自动刷新/自动采样联动
- 调用 `api` 的业务动作函数
- 少量导航、关闭、重置等局部辅助函数

#### `src/pages/AppContent.tsx`

主要承接：

- 顶部导航与 toolbar
- 全局 banner / action banner / warning banner
- loading 空态
- 一级页面切换与条件渲染
- 账号详情抽屉与切换确认面板挂载

这符合当前阶段的拆分目标：先把超长 JSX 与顶层展示编排从主入口剥离，但先不大改 API 边界与状态组织。

### 3.2 已拆出的页面

当前已完成第一轮页面级拆分：

- `src/pages/DashboardPage.tsx`
- `src/pages/AccountsPage.tsx`
- `src/pages/HandoffPage.tsx`
- `src/pages/NotificationsPage.tsx`
- `src/pages/StabilityPage.tsx`
- `src/pages/SettingsPage.tsx`

同时已拆出顶层 overlay 组件：

- `src/pages/AccountDetailDrawer.tsx`
- `src/pages/SwitchConfirmPanel.tsx`

Dashboard 首页现在聚焦：

1. 当前活跃账号总览
2. 多账号状态总览
3. 用量历史趋势
4. 账号时间轴
5. 推荐动作卡

同时将以下信息收束到次级 notice 区：

- 当前 `message`
- 最近切换接力卡
- 当前登录未绑定提示
- 官方扩容优先提示

这次收敛的目标是让首页更符合 `TASK.md` / `DESIGN.md` 中“当前状态 → 推荐动作 → 候选账号 → 趋势/时间轴”的主通路。

### 3.3 展示层 helper

以下展示 helper 已从 `App.tsx` 迁移到 `src/pages/viewModel.ts`：

- `statusText`
- `switchButtonText`
- `switchHintText`
- `accountModeLabel`
- `accountEmailLabel`
- `accountOfficialIdLabel`
- `accountUsagePercent`
- `accountResetTime`
- `notificationSourceText`
- `notificationActionText`
- 以及 Dashboard / 通知相关的格式化函数

迁移原则：

- 只迁纯展示、纯格式化逻辑
- 不迁依赖全局状态或触发动作的逻辑
- 保持旧文案和旧语义，不做无关改写

## 4. 当前后端能力

Rust 侧当前主要模块如下：

### 4.1 `auth.rs`

负责：

- 读取 Codex 官方登录状态
- 提取官方身份信息
- 诊断绑定环境
- 打开官方登录流程
- 校验真实绑定会话

### 4.2 `keychain.rs`

负责：

- macOS Keychain 凭证读写
- 会话引用与账号密钥管理
- 删除或更新账号相关安全凭证

### 4.3 `usage.rs`

负责：

- 真实用量读取
- 用量快照写入
- 最近快照查询
- 真实用量窗口数据整合

### 4.4 `switching.rs`

负责：

- 切换可行性判断
- 活跃账号切换
- 切换日志写入
- 切换回滚
- 切换接力卡草稿生成

### 4.5 `startup_health.rs`

负责：

- 启动健康检查
- 发布前环境检查的结构化输出

### 4.6 `lib.rs`

负责：

- Tauri commands 注册
- SQLite 初始化与查询编排
- DashboardOverview 聚合
- AccountDetail 聚合
- 通知、接力卡、设置、诊断等命令实现

## 7. 当前架构边界

### 7.1 前端边界

前端通过 `src/lib/api.ts` 调用 Rust command，当前主要接口包括：

- `bootstrap`
- `getOverview`
- `triggerSampling`
- `switchAccount`
- `bindCurrentCodexAccount`
- `verifyBoundAccount`
- `repairAccountAuth`
- `getAccountDetail`
- `listHandoffs`
- `createHandoff`
- `updateHandoff`
- `listNotifications`
- `getReleaseDiagnostic`
- `getStartupHealth`
- `previewCleanupDebugData`
- `cleanupDebugData`
- `updateSettings`

### 7.2 当前拆分原则

当前仍采用“先稳边界、再拆页面”的策略：

- 不先重构 Rust 命令层
- 不先引入新的状态管理库
- 先按页面边界把 `App.tsx` 拆薄
- 先把纯展示 helper 外移
- CSS 首轮尽量复用既有 class，不重做样式体系

这是为了控制改动面，避免“拆 JSX”演变成“大规模重构”。

## 8. 与旧原型文档的关系

仓库根目录中的 `TASK.md`、`DESIGN.md` 与原型文档仍然有参考价值，但需要注意：

- 它们记录的是更早阶段的产品目标与视觉约束
- `CodexSwitcherMac` 当前已进入真实工程阶段
- 不应再按“静态 prototype、无构建工具、无真实后端”的假设理解 Mac 端现状

当前更准确的理解方式是：

- `TASK.md` / `DESIGN.md` 继续约束信息架构、视觉语言与 unknown 语义
- `CodexSwitcherMac` 则是这些目标在真实工程中的落地版本

## 9. 当前验证方式

前端最基本验证：

```bash
cd CodexSwitcherMac
npm run build
```

当前该构建命令可通过。

后续人工回归时，建议重点检查：

1. Dashboard 首页顺序是否仍符合产品要求
2. unknown / 无真实数据时是否明确显示空态说明
3. 推荐切换、立即采样、管理账号跳转是否正常
4. 账号详情抽屉、切换确认面板、最近切换接力卡跳转是否正常
5. 通知中心过滤与账号关联跳转是否正常

## 10. 下一阶段建议

按当前代码状态，建议继续按以下顺序推进：

1. 继续收口 `App.tsx` 中剩余的派生逻辑和页面级 helper，让主入口进一步聚焦状态与动作
2. 视页面复杂度把 Dashboard / Accounts 内部的大卡片继续拆成局部组件，但保持现有 API 与状态边界不变
3. 在页面结构稳定后，再评估是否需要补充更清晰的 service/store 分层，而不是提前引入大而全抽象
4. 继续整理与当前真实工程相匹配的文档，避免开发文档继续落后于代码现状
5. 最后再处理样式整理与清理未使用选择器

## 11. 设计与实现约束

后续继续开发 Mac 端时，仍需遵守：

- 只做浅色主题
- 保持安静、克制、桌面效率工具感
- 遵守 `TASK.md` / `DESIGN.md` 规定的 Dashboard 首页顺序
- unknown 继续明确展示，不补假数据
- 不为了“看起来更工程化”而提前做过度抽象

当前最重要的方向不是推翻现状重写，而是在已落地的真实工程基础上继续稳步拆分和收敛。
