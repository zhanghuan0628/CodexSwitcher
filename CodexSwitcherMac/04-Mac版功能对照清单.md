# CodexSwitcher Mac 功能对照清单

## 1. 说明

本清单用于回答三个问题：

- 当前 Mac 版到底实现了哪些功能
- 哪些功能只是半实现
- 下一步最该补哪些点

状态定义：

- `已实现`：主链路可用
- `半实现`：有页面和逻辑，但真实性、稳定性或完成度不足
- `未实现`：目标功能尚未真正落地

---

## 2. 项目整体判断

当前 `CodexSwitcherMac` 已经不是纯文档或静态原型，而是一个可编译运行的：

- `Tauri + React + TypeScript + Rust + SQLite`

桌面应用。

当前阶段可定义为：

`真实账号第一阶段 MVP`

整体完成度建议判断为：

- UI 与桌面工作台：`80%`
- 本地业务链路：`75%`
- 真实账号能力：`55%`
- 真实额度与预测：`40%`
- 工程化与可维护性：`50%`

综合完成度：`65% ~ 75%`

## 4. 已实现能力清单

## 4.1 桌面应用基础壳

已实现：

- Tauri 宿主
- React 前端
- Rust 后端
- SQLite 本地数据
- Tray 菜单
- 前端构建成功

当前结论：

- 这是一个真实可运行项目，不是静态 demo

## 4.2 仪表盘

已实现：

- 当前活跃账号展示
- 多账号状态展示
- 用量历史图表区域
- 账号时间轴区域
- 推荐动作区域
- 切换日志区域

当前结论：

- 仪表盘结构完整，可作为演示和继续开发基础

## 4.3 账号管理

已实现：

- 绑定当前官方登录态
- 诊断绑定环境
- 设为默认账号
- 验证账号
- 修复授权
- 删除账号

当前结论：

- 账号中心主能力已经成型

## 4.4 真实账号主链路

已实现：

- 读取当前官方登录态
- 保存 Keychain 凭证引用
- 写入 SQLite 元信息
- 切换前检查
- 切换后验证
- 失败回滚
- 结果记录通知和日志

当前结论：

- 已经具备“真实切换第一阶段”的骨架能力

## 4.5 接力与通知

已实现：

- 手动创建接力卡
- 编辑接力卡
- 复制接力卡
- 切换前自动生成系统接力卡
- 记录真实绑定/切换/设置事件通知

当前结论：

- 接力功能已经可用，不再是单纯文档描述

---

## 5. 半实现能力清单

## 5.1 真实额度采样

现状：

- Rust 侧已经尝试接真实额度接口
- 已能区分真实数据与未知状态
- 但真实额度来源并不稳定

问题：

- 接口稳定性和可读性受限
- 并非所有真实账号都能稳定拿到额度
- 前端必须保守降级

结论：

- 这块是当前最明显的短板

## 5.2 历史图表

现状：

- 图表区域已存在
- 已有数据结构和展示逻辑

问题：

- 对真实账号来说，常常只能显示保守结果
- 当前并不是完全真实历史图

结论：

- UI 已实现，数据层还没完全站稳

## 5.3 时间轴视图

现状：

- 页面已做
- 账号泳道已展示

问题：

- 已收敛为真实快照优先，缺少数据时保守 unknown
- 不是基于稳定真实快照的精确预测

结论：

- 当前适合演示，不适合当成严格决策依据

## 5.4 推荐引擎

现状：

- 已有推荐文案
- 已有保守逻辑

问题：

- 仍受真实额度链路不稳定影响
- 推荐更多是“谨慎建议”，不是强决策引擎

结论：

- 可用，但还不够强

---

## 6. 未实现或未完成项

## 6.1 自动切换

当前没有：

- 后台无感自动切换
- 达阈值自动切号
- 后台自动恢复后再切回

当前结论：

- 产品仍是“辅助切换工具”，不是自动调度器

## 6.2 完整应用内登录接管

当前没有：

- 完整的应用内官方登录流程
- 完整的绑定向导式登录接管

当前结论：

- 目前更偏“复用已有登录态”

## 6.3 Rust 模块化

当前问题：

- 大量逻辑集中在单一 `src-tauri/src/lib.rs`
- 后续继续扩展会越来越难维护

当前结论：

- 这是必须尽快处理的工程债

## 6.4 文档同步

当前问题：

- `REAL_ACCOUNT_PLAN.md` 对现状描述已落后于代码
- 项目文档和当前实现之间有时间差

当前结论：

- 文档需要补一次对齐

---

## 7. 当前最关键的问题

按优先级排序：

1. 真实额度链路不稳定
2. 历史演示账号路径已清理，仍需持续防回归
3. Rust 逻辑未模块化
4. 图表 / 时间轴 / 推荐缺真实数据时保持 unknown
5. 文档与代码不同步

---

## 8. 结论

一句话判断：

当前 Mac 版已经完成了“真实桌面工作台第一阶段”，主壳、账号中心、真实切换、回滚、接力、托盘都已经有了；但产品要进入更稳的可用阶段，下一步必须优先解决真实额度、账号体系收敛和 Rust 模块化问题。
