# CodexSwitcher Mac 下一阶段 7 天排期

## 1. 排期目标

本轮 7 天排期只做 Mac 版，目标不是继续铺 UI，而是把当前 MVP 从“能演示”推进到“更稳、更可信、更可维护”。

本轮核心目标：

- 收敛真实账号主链路
- 明确真实额度能力边界
- 彻底移除演示逻辑干扰
- 开始 Rust 模块化

## 2. 节奏原则

- 优先修主链路，不做分散优化
- 优先让“真实能力”比“演示能力”更可信
- 每天只做一个主目标
- 每天必须有可验证结果

## 3. 本轮完成标准

- 账号中心不再把“手工演示账号”作为主流程
- 真实账号链路的状态表达更清晰
- 真实额度能力边界明确到 UI 和逻辑中
- Rust 至少完成第一批模块拆分
- 文档与当前实现对齐

---

## Day 1：收敛账号中心主路径

### 主目标

把账号中心从“真实 Codex 账号主路径”收敛到“真实绑定优先”。

### 任务

- 识别并梳理当前账号中心里所有演示入口
- 降级 `create_account` 对外暴露程度
- 去掉或弱化“手工编辑 status / auth_state”作为主操作
- 调整账号中心文案，明确“真实绑定优先”

### 验收标准

- 用户进入账号中心时，主入口是“绑定当前官方登录态”
- 普通用户不会误以为“手动创建账号卡片”是正式路径

---

## Day 2：整理真实账号状态机

### 主目标

把真实账号的状态表达和按钮逻辑彻底梳理清楚。

### 任务

- 统一账号状态与授权状态组合逻辑
- 梳理切换按钮文案、禁用条件和提示文案
- 补齐真实账号在以下场景下的展示：
  - 可切换
  - 校验异常
  - 已失效
  - 恢复中

### 验收标准

- 账号列表中每个真实账号都能明确回答：
  - 当前能不能切
  - 为什么不能切
  - 用户下一步该做什么

---

## Day 3：收真实额度链路边界

### 主目标

把真实额度能力从“尝试读取”收敛成“可解释、可降级”的稳定策略。

### 任务

- 梳理真实额度读取成功、失败、无权限、无返回四种状态
- 统一 `real_usage / unknown` 的 UI 和逻辑含义
- 让仪表盘、图表、推荐都明确展示“真实 / 未知”
- 去掉会误导用户的伪真实文案

### 验收标准

- 用户能一眼看出当前数据是否真实可验证
- 没有稳定真实额度时，界面会明确写 `unknown`

---

## Day 4：重构采样与推荐逻辑

### 主目标

把采样和推荐逻辑从“混合演示感”改成“保守可信”。

### 任务

- 梳理 `trigger_usage_sampling` 的数据来源分支
- 优化推荐逻辑：真实快照优先，未知状态保守输出
- 降低 seed 数据对推荐结果的影响
- 补充采样结果消息文案

### 验收标准

- 推荐动作不会把unknown 当成精确结论
- 采样提示能清晰告诉用户这次拿到的是什么数据

---

## Day 5：拆 Rust 第一批模块

### 主目标

把 `lib.rs` 中最重的职责先拆出第一批模块。

### 任务

- 新建并拆出：
  - `db`
  - `keychain`
  - `account_manager`
  - `switch_orchestrator`
- `lib.rs` 只保留状态注入、command 注册和装配
- 保持现有测试和构建可过

### 验收标准

- `lib.rs` 明显变薄
- 主要账号/切换/存储逻辑已搬到独立模块
- `cargo test` 或至少前端构建不受破坏

---

## Day 6：收 UI 与交互细节

### 主目标

补齐“真实能力阶段”需要的 UI 细节，不再让界面像混合 demo。

### 任务

- 调整仪表盘说明文案
- 调整账号中心说明块
- 统一图表和时间轴中的可信度标识
- 检查 banner、提示文案、空态、错误态

### 验收标准

- 页面不再出现“能力边界模糊”的提示
- 用户能明显区分“真实数据”和“未知兜底”

---

## Day 7：回归测试 + 文档同步

### 主目标

把代码现状和文档同步到同一版本。

### 任务

- 回归验证：
  - 绑定
  - 校验
  - 切换
  - 回滚
  - 接力
  - 设置
- 更新 `REAL_ACCOUNT_PLAN.md`
- 补充 README 或当前阶段说明
- 记录已知问题与下一轮计划

### 验收标准

- 文档与代码现状一致
- 当前阶段能力边界写清楚
- 可以基于新文档继续下一轮开发

---

## 4. 本轮优先级

### P0

- 真实账号主路径收敛
- 真实额度边界明确
- Rust 第一批模块拆分

### P1

- 推荐逻辑保守化
- UI 提示与可信度标签统一
- 文档同步

### P2

- 更细的时间轴优化
- 更强的推荐引擎
- 更多系统级设置能力

---

## 5. 一句话策略

这 7 天不要再追求“再加几个新功能”，而是先把当前 Mac 版从“能演示的真实化 MVP”收成“可信的真实化第一阶段产品”。  
先把真实账号、真实额度边界和代码结构站稳，后面的图表、时间轴和推荐才值得继续做深。
