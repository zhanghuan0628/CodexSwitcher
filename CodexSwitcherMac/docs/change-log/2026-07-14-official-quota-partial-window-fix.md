# 官方账号部分额度窗口兼容修复

- 变更背景：官方账号登录态有效，但账号页和首页始终显示额度未知。脱敏请求确认当前官方额度接口对部分账号只返回 7 天窗口，`secondary_window` 为空；旧实现要求 5h 与 7d 两个窗口同时存在，因此丢弃了整次真实采样。
- 本次变更内容：按 `limit_window_seconds` 识别 5h / 7d 窗口，不再依赖主次字段顺序；允许只包含一个有效窗口的官方响应生成真实快照；缺失窗口使用内部未知标记，并在页面、详情、推荐和托盘中统一显示为 `--`，不伪造百分比或恢复时间。
- 涉及范围：Mac 端官方账号真实额度解析、快照写入、额度展示、推荐排序和托盘摘要。
- 是否影响配置：否。
- 是否影响接口或使用方式：否；现有 Tauri 命令与前端字段保持兼容，缺失窗口的百分比内部值为 `-1`，所有用户可见位置显示为 `--`。
- 是否向后兼容：是；原有同时包含 5h / 7d 的响应继续按原口径展示，单窗口响应现在可以展示已确认的真实窗口。
- 验证方式：脱敏探测当前官方接口响应；`npm run build`；`cargo test --no-fail-fast`（87 项通过）；新增经典双窗口与单 7d 窗口解析测试。
- 风险与注意事项：不同订阅计划可能只提供部分额度窗口。应用只展示官方响应中实际存在的窗口，不根据其他窗口推测缺失额度。
