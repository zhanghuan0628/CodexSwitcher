# 项目会话两栏与归档候选修复

- 时间：2026-08-28
- 类型：编辑现有列表行为；Tauri 命令、参数、返回字段和数据库结构不变。

## 需求与背景

用户明确两栏规则：**左侧仅为当前账号 / Key 的会话；右侧按其他账号 / Key 分组，从右侧勾选会话导入左侧。** 初版修复将全部身份放到左侧，理解有误，已按此规则纠正。

原有候选读取只查未归档线程，而账号隔离把其他 Key 的线程归档，因此右侧无法列出它们。已保存记录也曾按当前可见主线程 ID 过滤并限制 100 条，导致历史记录丢失于展示。

## 最终变更

- 左侧只显示当前身份已保存的记录和匹配该身份的本地主会话。没有当前身份时左侧为空，不能导入。入口文案为“当前账号 / Key 会话”“当前身份的全部项目”，不再出现“全部身份”。
- 右侧合并其他身份的已保存历史和本地候选，按账号 / Key → 项目 → 会话分组；排除当前身份的会话，按会话 ID 去重。已保存归属优先，不能仅因本地候选标签变化而将它归到当前账号。
- 右侧只有后端实际返回的可导入源会话可以勾选。未找到源会话的历史仍在右侧，标注“未找到可导入源会话”；身份/项目全选只选择可导入项，计数区分全部记录与可导入记录。
- 切换当前身份时清空选择，重新计算两栏。导入目标始终为当前账号 / Key。
- 已保存历史不再受当前侧栏可见性或 100 条上限限制；仍排除已知非主线程和内部审查记录。
- 候选列表和导入操作均包含 Switcher 标记的隔离归档线程；用户手动归档仍不进入候选池，查询不执行取消归档。
- 查询记录库不再触发 Codex 归档同步；账号切换的隔离逻辑保留。
- 精确匹配 Key provider，界面使用原厂商/Key 昵称及官方账号昵称，不显示 `codexswitcher-key-*`。身份已删除且原名称不存在时标为历史身份，不猜测名称或归到当前账号。
- 先判断归档范围及文件是否存在，再统计消息，避免扫描不显示的归档文件。

## 范围与兼容性

- 修改 Mac 的 `HandoffPage`、`projectSessionViewModel` 和 Rust 会话读取；Windows 不变。
- 无新增配置或公开接口字段；右侧 `importable` 仅为前端派生状态。
- 不恢复已删除的 rollout 文件；缺少真实源会话时不伪造导入成功。
- 修正额度读取负向测试的前提：禁用 fixture 的钥匙串回退，使其确实没有可用登录快照。生产额度读取逻辑未改动。
